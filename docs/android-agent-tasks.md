# Android: план реализации для агентов

Разбивка [android-plan.md](android-plan.md) на задачи, которые можно раздать агентам.
Каждая задача самодостаточна: вход, контракт, DoD, границы. Один агент = одна задача = один
коммит в `feature/android`.

## Правила для всех агентов

1. **Ветка `feature/android`.** `master` не трогать. Коммит только после зелёных проверок.
2. **Файлы правим Read/Edit/Write**, не heredoc'ами из bash. Bash — сборка, тесты, git, ssh.
3. **Зелёный набор перед коммитом** (фронт): `npm run typecheck && npm run lint && npm test`.
   Бэк: `.venv/bin/pytest` в `laereNorskBackand`.
4. **Веб не должен деградировать.** Всё нативное — за флагом `Capacitor.isNativePlatform()`.
   Любая задача, ломающая веб-сборку, считается проваленной, даже если Android работает.
5. **Не деплоить.** Прод (Hetzner) катает человек; агент готовит диф и пишет, что нужно
   применить на сервере.
6. **Не изобретать эндпоинты.** Бэкенд-контракты ниже сверены с кодом; если чего-то не хватает —
   задача останавливается и репортит, а не дописывает роутер молча.
7. В отчёте: что сделано, чем проверено, что осталось человеку.

## Роли

| роль | задачи | чем должен владеть |
|---|---|---|
| **WEB** | A1, A2, A5, A7 | React/Vite, vitest, api.js |
| **NATIVE** | A3, A4, A6 | Kotlin, Android SDK, Gradle, Capacitor-плагины |
| **BACK** | A8, A9 | FastAPI, pytest, sqlite |
| **HUMAN** | H1–H6 | ключи, консоли, физический телефон, деньги |

Агент не может: сгенерировать keystore с реальным паролем, зарегистрировать Play Console,
завести OAuth-клиент в Google Cloud, поставить APK на телефон, снять скриншоты для карточки.
Всё это — H-задачи, и они блокируют часть A-задач.

# A1. Скелет Capacitor — WEB+NATIVE, 0.5 дня

**Вход:** H1 (package id). **Блокирует:** всё.

```bash
npm i @capacitor/core @capacitor/cli @capacitor/android @capacitor/preferences @capacitor/app
npx cap init "Norsk" space.learnnorsk.app --web-dir=dist
npx cap add android
npm run build && npx cap sync
```

Работы:

1. `capacitor.config.json` в корне; `android/` коммитим целиком (это Gradle-проект, туда руками
   лягут активити из A3/A4 — генерить его заново нельзя).
2. `.gitignore`: `android/app/build/`, `android/.gradle/`, `android/local.properties`,
   `android/app/release/`, `*.keystore`, `*.jks`.
3. `package.json`: скрипты `android:sync` (`npm run build && npx cap sync android`),
   `android:open`.
4. **Аппаратная «назад»**: `@capacitor/app` `backButton` → `history.back()`, а на корневом
   маршруте — `App.exitApp()`. Регистрировать только на нативе.
5. **Safe-area**: `env(safe-area-inset-*)` в `src/styles/app.css`. Отдельно проверить
   `useAutoHideNav` — авто-скрытие панелей завязано на края экрана, под вырезом поедет.
6. Splash + иконка из `public/web-app-manifest-512x512.png`.

**Границы:** авторизацию, токены, нативные активити не трогаем — это A2/A3.

**DoD:** debug-APK ставится на телефон (H-проверка), вход **по паролю** работает, учёба / база /
онлайн открываются, «назад» не выбрасывает из приложения с внутреннего экрана.
`npm run build` для веба по-прежнему собирается и деплоится как раньше.

# A2. Мост токенов + Google Sign-In — WEB, 1 день

**Вход:** A1, H2. **Блокирует:** A3.

## A2.1. Адаптер хранилища в `ApiService`

Сейчас токены — синхронный `localStorage`
([api.js:33-56](../src/components/tools/api.js#L33-L56)), `logout()` —
[api.js:364](../src/components/tools/api.js#L364), инстанс создаётся на импорте модуля
([api.js:373](../src/components/tools/api.js#L373)).

**Главная ловушка:** `@capacitor/preferences` **асинхронный**, а `_initTokens()` синхронный и
вызывается в конструкторе. Наивная замена = первый запрос уходит без токена, юзер видит экран
логина при каждом старте.

Контракт:

- адаптер `tokenStore` с двумя реализациями: web → `localStorage`, native → `Preferences`
  (это `SharedPreferences`, читается из Kotlin — ради A3);
- в памяти `ApiService` токены остаются синхронными (`this.accessToken`), адаптер — только
  персистенс;
- `api.ready()` — промис гидрации; в [main.jsx](../src/main.jsx) `await api.ready()` **до**
  `createRoot`, иначе первый рендер решит, что юзер не залогинен;
- **все** записи токенов идут через адаптер: `_setTokens`, `logout`, а также запись после
  `/refresh` ([api.js:80](../src/components/tools/api.js#L80));
- сохранить существующую валидацию «похоже на JWT» и чистку старых AES-блобов.

**Гонка, которую нельзя пропустить:** `/refresh` **ротирует refresh-токен** (пишутся оба). После
A3 нативная активити тоже умеет рефрешить. Если она обновит токены, пока WebView держит старый
`this.refreshToken` в памяти, WebView получит 401 на рефреш и разлогинит юзера. Поэтому:
**на `App` resume (`@capacitor/app` `appStateChange` → `isActive`) перечитывать токены из
Preferences в память.** Тест на это обязателен.

**Тесты (vitest, node-окружение):** гидрация из пустого хранилища; из валидной пары; из битой пары
(чистится); `_setTokens` пишет в адаптер; resume-регидрация подхватывает токены, записанные
«снаружи». Веб-путь остаётся на моке `localStorage` — старые тесты не переписывать.

## A2.2. Google Sign-In

Google блокирует веб-флоу в WebView (`disallowed_useragent`) — существующая кнопка на нативе
просто не сработает.

- нативный плагин Google Auth, `serverClientId` = веб-клиент (см. H2);
- `id_token` уходит в существующий `/auth/google`, **бэкенд не трогаем** — `aud` совпадает;
- в UI: на нативе кнопка вызывает плагин, в вебе — как сейчас. Ветвление одно, в компоненте
  логина, не в `api.js`.

**DoD:** на телефоне вход через Google проходит, токены переживают перезапуск приложения,
`npm test`/`typecheck`/`lint` зелёные, веб-логин не изменился.

# A3. `PROCESS_TEXT` — NATIVE, 1 день. **Главная фича**

**Вход:** A2 (токены в `SharedPreferences`). **Блокирует:** H5.

Kotlin-активити, **не WebView**: 1.5–2 с холодного старта поверх чужого приложения убивают
ценность фичи.

## Манифест

```xml
<activity android:name=".AddWordActivity"
          android:label="Norsk"
          android:theme="@style/Theme.Norsk.BottomSheet"
          android:excludeFromRecents="true">
  <intent-filter>
    <action android:name="android.intent.action.PROCESS_TEXT"/>
    <category android:name="android.intent.category.DEFAULT"/>
    <data android:mimeType="text/plain"/>
  </intent-filter>
</activity>
```

`android:label` держать коротким: в тулбаре выделения помещается 1–2 сторонних пункта.

## Поток

1. `Intent.EXTRA_PROCESS_TEXT` → нормализация: trim, обрезка пунктуации, нижний регистр, кап длины
   (бэк режет слово на 80 символах — [pool.py:298](../../laereNorskBackand/routers/pool.py#L298)).
2. Токен из `SharedPreferences` (ключи те же, что пишет A2.1). Нет → «Войдите в приложении» +
   кнопка запуска `MainActivity`.
3. Bottom-sheet: слово, перевод, выбор набора, «Добавить».
4. Наборы: `GET /sets` → `[{id, name, studying, count}]`
   ([sets.py:52](../../laereNorskBackand/routers/sets.py#L52)).
5. **Разрешение выделенного текста в слово пула — здесь основная неочевидность.**
   `POST /sets/{id}/words` принимает `{norwegian}`, но внутри делает `get_pool_id(word)` и при
   промахе отвечает **400 «No words»**
   ([sets.py:106-125](../../laereNorskBackand/routers/sets.py#L106-L125)).

   `GET /pool/search?q=<текст>&limit=5` → `{results: [...]}`, элемент =
   `{word, translate, part_of_speech, inPool, viaForm?}` — **`pool_id` в ответе НЕТ**
   ([db/pool.py:1565](../../laereNorskBackand/db/pool.py#L1565)). Отсюда:
   - добавлять **по `{norwegian: item.word}`**, а не по id;
   - **`item.word` — это лемма, и слать надо именно её.** Поиск понимает словоформы через
     ordbank (`gikk` → `gå`, помечено `viaForm`) — а в статье выделяют как раз склонённую
     форму. Отправишь выделенный текст как есть — 400 на половине слов;
   - `inPool: false` = слово известно банку/лексикону, но записи в пуле нет → добавление
     упадёт. Тут кнопка «Сгенерировать» → `POST /pool/generate {word}` (**под LLM-rate-limit**,
     возможен 429 — показать «попробуйте позже», не крутить ретраи);
   - **омонимы через этот эндпоинт не разруливаются**: `pool_id` не отдаётся, а
     `get_pool_id(word)` без `pos` берёт старшую запись
     ([db/pool.py:277](../../laereNorskBackand/db/pool.py#L277)). Для v1 это принимаем: слово
     уедет в набор с одним из значений. Не изобретать обход, не дописывать роутер — если
     мешает, репортить.
6. **401 → активити сама дёргает `POST /refresh {refresh_token}`** и записывает **оба** новых
   токена обратно в `SharedPreferences` (рефреш ротируется!). Один ретрай, не цикл.
7. Успех → toast, `finish()`. Пользователь остался в своей статье.

## Обязательные детали UX

- **Последний набор запоминается** — в 90% случаев добавление становится одним тапом.
- **Офлайн/сетевая ошибка** → слово в локальную очередь (Room или json в `filesDir`), синк при
  следующем открытии приложения. Очередь должна пережить убийство процесса.
- Никакой блокирующей работы на main-thread; шит показывается сразу, перевод дозагружается.

**Ограничение, которое надо принять:** в приложениях со своим меню выделения (часть PDF-читалок,
местами Firefox) пункта не будет. Это архитектура Android, не баг — объяснить в онбординге (A7).

**DoD:** выделил слово в Chrome → «Norsk» → шит → слово в наборе, Chrome не свернулся. Протухший
access-токен → активити молча рефрешит и добавляет. Авиарежим → слово в очереди, после открытия
приложения оказывается в наборе.

# A8. CORS для Capacitor — BACK, 30 мин

**Вход:** нет. Делать первым — без этого умрёт первый же запрос из APK.

CORS fail-closed после аудита безопасности: `allow_origins` — точный список из `CORS_ORIGINS`
(`main.py:31`). Origin WebView на Android — **`https://localhost`**: в Capacitor 8
`server.androidScheme` по умолчанию `https` (`CapConfig.java`), и именно этот Origin уходит в
запросах. `http://localhost` — только запасной, если схему когда-нибудь переключат.

- **Кода в `main.py` менять не нужно** — список берётся из env. Задача: добавить
  `https://localhost` и `http://localhost` в `CORS_ORIGINS` прода и в локальный `.env`/`config`,
  дописать это в README/AGENTS.md и **выдать человеку точную строку для H6**.
- `capacitor://localhost` (iOS) **не добавлять** — iOS в плане нет, лишний origin в белом списке
  не нужен.
- Тест: pytest на preflight с `Origin: http://localhost` → `access-control-allow-origin` в ответе.

**DoD:** pytest зелёный, инструкция для прода написана. Деплой — человек.

# A9. FCM на бэке — BACK, 1 день

**Вход:** нет, можно параллельно всему.

Web Push в Capacitor WebView не работает (нет Service Worker Push), поэтому напоминания
«13ч бездействия» на нативе требуют FCM.

- `webpush.py` **остаётся** для веба — не рефакторить, не сливать;
- рядом таблица `fcm_subscriptions` (user_id, token, platform, created_at, уникальность по токену)
  + эндпоинты subscribe/unsubscribe по образцу существующих;
- отправка через **FCM HTTP v1** (service-account JSON, OAuth2-токен; legacy-ключи отключены);
  секрет — в env, как VAPID;
- **воркер шлёт в оба канала с дедупом по юзеру** — иначе у кого есть и веб, и приложение,
  получают два уведомления. Дедуп — это и есть основная логика задачи, а не отправка;
- протухший FCM-токен (`UNREGISTERED`/`INVALID_ARGUMENT`) → удалять подписку, как это уже делается
  для web-push;
- роутер подключать так же защищённо, как push-роутер в `main.py` (падение зависимости не должно
  ронять бэкенд).

**Тесты:** subscribe/unsubscribe, дедуп «веб+натив у одного юзера = одно уведомление», чистка
протухшего токена. Отправку мокать.

**DoD:** pytest зелёный, контракт эндпоинтов записан для A6.

## Что найдено в коде и обязано попасть в реализацию

1. **`_initTokens` синхронный, `Preferences` — нет.** Без `await api.ready()` перед первым
   рендером приложение будет считать юзера разлогиненным при каждом старте. (A2.1)
2. **`/refresh` ротирует refresh-токен.** Два независимых клиента (WebView и нативная активити)
   на одной паре токенов → разлогин, если не перечитывать хранилище на resume. (A2.1, A3)
3. **`POST /sets/{id}/words {norwegian}` даёт 400 на слове, которого нет в пуле.** Нативной
   активити нужен путь `/pool/search` → (омонимы: выбор) → при промахе `/pool/generate`, который
   ещё и под LLM-rate-limit с 429. Без этого фича будет валиться на каждом непопулярном слове. (A3)
4. **8 МБ base64 на `/ocr`.** Скриншот телефона с большим экраном в лимит упирается — ужимать в
   Kotlin обязательно, не в JS. (A4)
5. **CORS fail-closed** — правится env'ом, а не кодом; без `http://localhost` не пройдёт ни один
   запрос из APK. (A8, H6)
6. **`sw.js` внутри APK опасен**, а не просто бесполезен: закешированный бандл переживёт
   обновление приложения. (A5)

## Риски

- **SHA-1 не тот** — Google-вход валится с невнятной ошибкой на релизной подписи, если в Cloud
  Console только debug-отпечаток. Теряется час.
- **Play App Signing перевыпускает ключ** — SHA-1 брать из Play Console, не из своего keystore.
- **Рассинхрон версий** — веб катится мгновенно, приложение через Play (часы). Ломающие изменения
  API теперь надо версионировать: часть пользователей на старом клиенте. У чисто веб-версии этой
  проблемы не было.
- **Потеря keystore** — обновления невозможны, только новое приложение с нуля.

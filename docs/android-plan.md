# Android-версия: план

Цель — нативное Android-приложение поверх существующего React-фронта, ради двух фич,
которых в вебе не существует в принципе:

1. **`PROCESS_TEXT`** — выделил слово в любом приложении (Chrome, почта, читалка) →
   пункт «Norsk» в тулбаре выделения → слово улетело в набор, не выходя из статьи.
2. **`SEND image/*`** — «Поделиться» скриншотом → импорт слов с фото (уже существующий
   пайплайн `/ocr` → правка → `/import-words`).

iOS в этом плане нет осознанно: там аналога `PROCESS_TEXT` не существует (сторонние
приложения не могут добавлять пункты в системное меню выделения), фича деградирует до
«Поделиться → Norsk» в три тапа, плюс нужен Mac, $99/год и App Group для Share Extension.
Возвращаться к iOS — только после того, как станет видно, что фичей пользуются.

## Технология

**Capacitor** (не React Native, не TWA):

- React-код переиспользуется целиком, переписывать нечего;
- `android/` — обычный Gradle-проект в репе, куда руками кладутся нативные активити;
- `dist/` кладётся внутрь APK, приложение работает офлайн;
- iOS-таргет добавляется одной командой, если когда-нибудь понадобится.

TWA отпадает: в него нельзя нормально добавить нативные активити, а без них обе фичи
невозможны.

### Что уже удачно сложилось

- [`main.jsx:21`](../src/main.jsx#L21) — `createHashRouter`. `BrowserRouter` ломается на
  локальном origin, у нас его нет.
- [`api.js:373`](../src/components/tools/api.js#L373) — абсолютный `VITE_API_URL`.
  Относительные пути к API пришлось бы переписывать.
- [`auth.py:97`](../../laereNorskBackand/auth.py#L97) `_verify_google` проверяет
  `aud == GOOGLE_CLIENT_ID`. Нативный Google Sign-In с `serverClientId` = наш веб-клиент
  выдаёт `id_token` ровно с этим `aud` → `/auth/google` работает **без правок бэкенда**.

## Этап 1. Скелет: APK на телефоне — 0.5 дня

```bash
npm i @capacitor/core @capacitor/cli @capacitor/android @capacitor/preferences @capacitor/app
npx cap init "Norsk" space.learnnorsk.app --web-dir=dist
npx cap add android
npm run build && npx cap sync && npx cap open android
```

Работы:

1. **CORS на бэке** — добавить в `CORS_ORIGINS` origin'ы Capacitor на Android:
   **`https://localhost`** (дефолтная схема WebView в Capacitor 8 — именно этот Origin
   уходит в запросах) и `http://localhost` (на случай, если `server.androidScheme`
   переключат на `http`). CORS fail-closed после аудита безопасности → без этого умрёт
   первый же запрос. Правится env'ом, `main.py` не меняется.
2. **Аппаратная кнопка «назад»** — `@capacitor/app` + `router.navigate(-1)`. По умолчанию
   закрывает приложение с любого экрана.
3. **Safe-area** — `env(safe-area-inset-*)` в `src/styles/app.css`. Отдельно проверить
   авто-скрытие панелей навигации (`useAutoHideNav`) — оно завязано на края экрана.
4. **`sw.js` не регистрировать на нативе** — ассеты локальные, пуши переезжают на FCM.
5. **Splash + иконка** из `public/web-app-manifest-512x512.png`.

**Готово, когда:** APK ставится на телефон, вход по паролю работает, учёба / база /
онлайн-режим работают.

## Этап 2. Мост токенов + Google OAuth — 1 день

### 2.1 Хранилище токенов

Сейчас `access_token` / `refresh_token` лежат в `localStorage`
([`api.js:34-55`](../src/components/tools/api.js#L34-L55)). Нативной активити они оттуда
недоступны — а ей они нужны (этап 3).

Вводим адаптер хранилища в `ApiService`:

- веб → `localStorage`, как сейчас;
- натив → `@capacitor/preferences` (это `SharedPreferences`, читается из Kotlin).

Один источник правды с обеих сторон. Это предпосылка для этапа 3, отдельной ценности не
несёт.

### 2.2 Google Sign-In

Google блокирует свой веб-флоу внутри WebView (`disallowed_useragent`) — текущая кнопка
входа в приложении просто не заработает.

- нативный плагин Google Auth, в конфиге `serverClientId` = **существующий веб-клиент**
  `296014238677-a9281g65p8i6crrp6u3hr3ufgirf6t1r`;
- в Google Cloud Console завести OAuth-клиент типа **Android** с SHA-1 отпечатком
  keystore — **и релизного, и debug**, иначе не потестишь локально;
- бэкенд не трогаем: `aud` совпадает, `/auth/google` принимает `id_token` как есть.

## Этап 3. `PROCESS_TEXT` — главная фича — 1 день

### Манифест

```xml
<activity android:name=".AddWordActivity"
          android:label="Norsk"
          android:theme="@style/Theme.Norsk.BottomSheet"
          android:excludeFromRecents="true">
  <intent-filter>
    <action android:name="android.intent.action.PROCESS_TEXT"/>
    <category android:name="android.intent.category.DEFAULT"/>
    <data android:mimeType="text/plain"/>
  </intent-filter>
</activity>
```

`android:label` **обязательно короткий**: в тулбаре выделения помещается 1–2 сторонних
пункта, длинное имя обрежется.

### Активити — нативная, НЕ WebView

Kotlin + bottom-sheet тема. Открывать WebView поверх чужого приложения нельзя: 1.5–2 с
холодного старта убивают всю ценность фичи.

Поток:

1. Берём `Intent.EXTRA_PROCESS_TEXT`, чистим (обрезка пунктуации, нижний регистр,
   кап длины).
2. Читаем токен из `SharedPreferences`. Нет → «Войдите в приложении» + кнопка открытия.
3. Шит: слово, перевод (запрос в базу), выбор набора, кнопка «Добавить».
4. `POST /sets/{set_id}/words` (`routers/sets.py:106`).
5. **401 → активити сама дёргает `/refresh`** и перезаписывает оба токена в
   `SharedPreferences`. Ради этого делался 2.1: WebView подхватит обновлённые токены
   при следующем старте.
6. Успех → toast, `finish()`. Пользователь остался в своей статье.

Детали, без которых фича раздражает:

- **офлайн / ошибка сети** → слово в локальную очередь, синк при следующем открытии
  приложения;
- **последний набор запоминается** — в 90% случаев добавление становится одним тапом.

**Ограничение, которое надо принять и объяснить в онбординге:** в приложениях со своим
меню выделения (часть PDF-читалок, местами Firefox) пункта не будет. Это архитектура
Android, не баг.

**Готово, когда:** выделил слово в Chrome → «Norsk» → шит → слово в наборе, Chrome не
свернулся.

## Этап 4. Скриншот → импорт — 0.5 дня

`ACTION_SEND` + `ACTION_SEND_MULTIPLE` с `image/*` на `MainActivity`. Здесь наоборот —
открываем полноценный WebView, потому что распознанное надо править.

1. Kotlin читает URI, **ужимает картинку**: бэк режет на 8 МБ base64
   (`routers/sets.py:181`), скриншот большого экрана в это упирается.
2. Отдаёт data-URL в JS через плагин-мост.
3. JS роутит на `#/sets` с флагом «есть входящее изображение», переиспользуя
   [`PhotoImportModal.jsx`](../src/components/sets/PhotoImportModal.jsx) →
   `/sets/{id}/ocr` → [`ImportReview.jsx`](../src/components/sets/ImportReview.jsx) →
   `/sets/{id}/import-words`.

Единственная новая ветка в UI: **набор ещё не выбран** — шарили-то извне, а `/ocr`
эндпоинт под набором. Значит перед OCR показываем выбор набора.

## Этап 5. Пуши через FCM — 1.5 дня

Web Push в Capacitor WebView не поддерживается (нет Service Worker Push). Напоминания
«13ч бездействия» на нативе требуют FCM.

- **фронт:** `@capacitor/push-notifications`, регистрация FCM-токена на нативе вместо
  VAPID-подписки;
- **бэк:** `webpush.py` остаётся для веба; рядом таблица `fcm_subscriptions` и отправка
  через FCM HTTP v1;
- **воркер** шлёт в оба канала, **дедуплицируя по юзеру** — иначе два уведомления тем,
  у кого и веб, и приложение.

Можно отложить за релиз: приложение без пушей полноценно работает.

## Этап 6. Релиз в Play

1. Release-сборка, подпись, `.aab`.
2. Play Console: карточка, скриншоты, **политика конфиденциальности** (обязательна — есть
   аккаунты и Google-вход), форма Data Safety.
3. **Закрытое тестирование: 12 тестировщиков непрерывно 14 дней** — требование для новых
   личных аккаунтов разработчика (Google снизил с 20 в 2025-м; проверить актуальное на
   момент регистрации). Аккаунты организаций освобождены, но им нужна бизнес-верификация
   с D-U-N-S.
4. Production.

**Запускать закрытый тест сразу после этапа 3**, параллельно с этапами 4–5. Иначе две
недели ожидания встанут в самый конец.

## Риски

- **SHA-1 не тот** — Google-вход валится с невнятной ошибкой при релизной подписи, если
  в Cloud Console только debug-отпечаток. Классика, теряется час.
- **Play App Signing перевыпускает ключ** — SHA-1 для Google Cloud брать **из Play
  Console**, а не из своего keystore.
- **Рассинхрон версий** — веб катится мгновенно, приложение через Play (часы). Ломающие
  изменения API теперь нужно версионировать: часть пользователей сидит на старом клиенте.
  У чисто веб-версии этой проблемы не было.
- **Потеря keystore** — обновления невозможны, только новое приложение с нуля.

## Стоимость владения

- Google Play раз в год требует поднять `targetSdk` → обновить Gradle/AGP, пересобрать,
  залить. Пара часов в год.
- Мажорные версии Capacitor раз в год, миграция по гайду.
- Play Console — $25 **единоразово**, не подписка.
